# Rate limits and quota

Two budgets apply, and they fail differently. The **rate limit** protects the service from how fast you ask; the **quota** prices how much data you take. Both report themselves on every response, so a well-behaved client never has to guess.

## Rate limits

Per account, per class of request, over a rolling minute. Classes are separate budgets: polling event discovery cannot exhaust your allowance for reading prices.

| Class | Endpoints | Per minute | Burst |
|---|---|---|---|
| Discovery | `/v2/events`, `/v2/entrants`, `/v2/competitors/{id}`, `/v2/sources`, item reads, `/v2/stream` connects | 600 | 300 |
| Prices | `/v2/odds` | 240 | 120 |
| Snapshot | `/v2/events/snapshot`, `/v2/events/{id}/snapshot` | 240 | 120 |
| Catalogue | `/v2/venues`, `/v2/meetings` | 60 | 30 |

These are the standard rates. Enterprise plans scale every class by a contracted multiple; `RateLimit-Policy` on any response reports the numbers that apply to your key.

The catalogue is tightest because those two endpoints summarise your entire window to return a short page — they are the most expensive reads on the API relative to what comes back. Ask for them when your integration starts, cache the result, and refresh occasionally. They are a reference table, not a feed.

Every response carries these, and they are declared on every operation in the OpenAPI document, so a generated client can read them without hardcoding names from this page:

| Header | Meaning |
|---|---|
| `X-RateLimit-Limit` | Requests per minute for this class. |
| `X-RateLimit-Remaining` | How many you can still send right now. |
| `X-RateLimit-Reset` | Seconds until the budget is full again. |
| `Retry-After` | On a `429`, how many seconds to wait. |

Over the limit is `429` with [`rate_limited`](/docs/api/errors#rate_limited). Wait `Retry-After` seconds and continue — no backoff calculation needed, we have told you the answer.

### Standard `RateLimit` headers

Every response also carries the IETF [`RateLimit-Policy` and `RateLimit`](https://datatracker.ietf.org/doc/draft-ietf-httpapi-ratelimit-headers/) fields, so a generic HTTP client or gateway can pace itself without knowing our header names. Each budget the request was checked against is one list member, named after its class (`discovery`, `prices`, `snapshot`, `catalogue`) or `monthly`:

```http
RateLimit-Policy: "prices";q=240;w=60, "monthly";q=2000000
RateLimit: "prices";r=239;t=1, "monthly";r=1998412;t=1209600
```

`q` is the quota, `w` the window in seconds, `r` what remains, and `t` the seconds until it resets. The monthly policy has no `w` because it follows the calendar month. The `X-RateLimit-*` headers stay and report the same numbers.

## Monthly quota

Your plan includes a monthly allowance of request units. Open access includes 2,000,000 units a month; the **API** and **API Live** plans state their allowance on the plan, and every response reports it:

| Header | Meaning |
|---|---|
| `X-RateLimit-Monthly-Limit` | Units included this month. |
| `X-RateLimit-Monthly-Used` | Units spent. |
| `X-RateLimit-Monthly-Remaining` | Uni

# Prices

Once you know which races you want, ask for their prices. One request covers every source we track for those races, paged like any list: a full race card is several hundred rows, so follow `next` (or pass `limit=200`) until it is absent. See [Pagination](/docs/api/pagination).

```bash
curl 'https://api-beta.betwatch.com/v2/odds?event=evt_7Kd2mQx4TnPbW9sVfHjLcR' \
  --header 'X-API-Key: YOUR_API_KEY'
```

```json
{
  "items": [
    {
      "id": "odd_7Kd2mQx4TnPbW9sVfHjLcR.4Bg9NpXqTmVdWs2HjFkLcR",
      "eventId": "evt_7Kd2mQx4TnPbW9sVfHjLcR",
      "key": "win",
      "entrantId": "ent_4Nb8xKpQ2mVfTdRcHjW5Ls",
      "source": { "id": "sportsbet", "name": "Sportsbet", "kind": "bookmaker" },
      "state": "available",
      "price": 3.2,
      "observedAt": "2026-08-17T04:02:11Z",
      "updatedAt": "2026-08-17T04:02:12Z"
    }
  ],
  "coverage": []
}
```

## Odds reads are always scoped

`/v2/odds` requires at least one of `event`, `entrant`, `meeting`, or `venue`. Without one it returns `422` [`filter_required`](/docs/api/errors#filter_required).

That is not an arbitrary restriction. Pricing every race in view means hydrating every race in view, which would be slow for you and expensive for us, to answer a question nobody actually has. Find races with [`/v2/events`](/docs/api/races), then price them:

```bash
# Several races at once
?event=evt_7Kd2mQx4TnPbW9sVfHjLcR,evt_3Nb8xKpQ2mVfTdRcHjW5Ls

# A whole meeting
?meeting=mtg_3Nb8xKpQ2mVfTdRcHjW5Ls

# One runner's prices, everywhere
?entrant=ent_4Nb8xKpQ2mVfTdRcHjW5Ls

# Only the sources you display
?event=evt_7Kd2mQx4TnPbW9sVfHjLcR&source=sportsbet,ladbrokes,betfair
```

Every parameter and response field: [`/odds` in the API reference →](https://beta.betwatch.com/api/docs#tag/prices/GET/odds)

## Reading a price

| Field | Meaning |
|---|---|
| `price` | Retained decimal odds, when known. May remain present on unavailable quotes; it is not by itself a current offer. Exchange rows use `bestBack` / `bestLay`. |
| `state` | `available`, `suspended`, `withdrawn`, `settled`, or `unknown`. Check this before showing `price`. |
| `source` | Who is offering it, with `kind` of `bookmaker`, `tote`, or `exchange`. |
| `key` | `win` or `place`. Place rows also carry `placesPaid`. |
| `entrantId`, `entrantName`, `entrantNumber` | The runner's identity and display labels. |
| `observedAt` | When Betwatch received the retained price value. An unchanged quote can keep an old value here. |
| `updatedAt` | When Betwatch wrote the retained price record, not a provider clock or proof of a price change. |
| `checkedAt` | Latest successful source-product observation. Failed fetches do not advance it. |
| `confirmation` | `confirmed` when the latest source check supports the quote; `unconfirmed` otherwise. A recent check alone does not make an unpriced observation a usable quote. A new price can be briefly `unconfirmed` (with `state=unknown`) until a source check that covers it is recorded, usually within 15 seconds. It stays `unconfirmed` while a newer check contradicts it. |
